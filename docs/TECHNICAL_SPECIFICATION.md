## 1. Назначение и границы

FlarePick — небольшое настольное приложение для предварительного отбора фотографий. Пользователь создаёт коллекцию, добавляет фотографии, просматривает их по одной и отмечает удачные или неудачные кадры. Приложение сохраняет коллекции и отметки между запусками.

Целевая аудитория — фотографы, которым нужен простой отбор кадров перед обработкой. Для учебного проекта достаточно законченного основного сценария, без возможностей профессионального менеджера фотобиблиотек.

### 1.1. Технологии

- Python 3.14.
- PyQt6: обычные виджеты и стандартный стиль системы.
- SQLite через стандартный модуль sqlite3.
- Pillow для чтения EXIF.
- PyInstaller для сборки на компьютере разработчика.

### 1.2. Основные решения

Коллекция — виртуальный альбом с названием. Пользователь создаёт её кнопкой и добавляет файлы через диалог множественного выбора. Привязки к папке и автоматического обновления нет.

Оригиналы остаются на своих местах. Приложение не копирует, не перемещает, не редактирует и не удаляет фотографии. В базе сохраняются пути ко всем добавленным кадрам, включая кадры без отметки.

Один файл разрешено добавлять в разные коллекции. Отметка относится к конкретной коллекции. Повторно добавить тот же путь в ту же коллекцию нельзя.

Три состояния фотографии:

| Значение в БД | Подпись в интерфейсе | Смысл |
| --- | --- | --- |
| unmarked | Unmarked | Без отметки |
| picked | Picked | Выбрана |
| rejected | Rejected | Отклонена |

### 1.3. Что не делаем

В эту версию не входят: фоновые потоки, постоянный кэш изображений, импорт целой папки, RAW/NEF и HEIC, редактирование, увеличение 100%, экспорт, поиск перемещённых файлов, теги, рейтинги, облако, аккаунты и синхронизация.

Нет требования выпускать три проверенные сборки за две недели. Достаточно проверить исходники и сборку на основной системе разработчика. Windows и Linux остаются возможными направлениями проверки, а не обещанием готового релиза.

## 2. Пользователь и сценарии

Единственная роль — пользователь приложения. Регистрация и администрирование не нужны.

### UC-01. Первый запуск

**Предусловия:** установлены зависимости или запущена готовая сборка.  
**Действия:** запустить приложение. Если базы нет, программа создаёт её и таблицы. Открывается главное окно.  
**Результат:** виден список коллекций либо сообщение «Создайте первую коллекцию».  
**Альтернатива/ошибка:** существующая база открывается без пересоздания; при невозможности открыть базу выводится сообщение, приложение закрывается без удаления данных.

### UC-02. Создание коллекции

**Предусловия:** главное окно открыто.  
**Действия:** нажать Create Collection, ввести название, подтвердить.  
**Результат:** новая пустая коллекция сохранена и выбрана.  
**Альтернатива/ошибка:** Cancel ничего не меняет; пустое или повторяющееся название не принимается, пользователь может исправить ввод.

### UC-03. Открытие коллекции

**Предусловия:** есть хотя бы одна коллекция.  
**Действия:** выбрать её в левом списке.  
**Результат:** появляется сетка миниатюр фотографий; миниатюры последовательно загружаются в основном потоке. Первый кадр выбран и показан крупно, если коллекция не пуста.  
**Альтернатива/ошибка:** для пустой коллекции показано предложение добавить фотографии; ошибка чтения БД показывается сообщением.

### UC-04. Добавление фотографий

**Предусловия:** выбрана коллекция.  
**Действия:** Add Photos → выбрать один или несколько JPEG/PNG → подтвердить.  
**Результат:** допустимые новые пути сохранены со статусом Unmarked, список обновлён.  
**Альтернатива/ошибка:** Cancel ничего не меняет; повторные пути пропускаются; неподдержанные или отсутствующие файлы пропускаются с общим сообщением. Ошибка БД отменяет добавление всего пакета. Повреждённое содержимое может обнаружиться при просмотре, такая запись показывает ошибку и может быть исключена из коллекции.

### UC-05. Просмотр и переключение

**Предусловия:** в коллекции есть фотографии.  
**Действия:** выбрать миниатюру либо нажать Previous/Next.  
**Результат:** в центре показана выбранная фотография, справа её EXIF, снизу статус.  
**Альтернатива/ошибка:** на границах соответствующая кнопка недоступна; нечитаемый кадр заменяется заглушкой, можно перейти к следующему.

### UC-06. Отбор

**Предусловия:** выбрана фотография.  
**Действия:** нажать Pick, Reject или Unmark.  
**Результат:** статус сохранён в БД и отображён рядом с именем файла. Pick заменяет Reject и наоборот; Unmark снимает любую отметку. После отметки текущий кадр остаётся выбранным.  
**Альтернатива/ошибка:** повторное назначение того же статуса ничего не меняет; при ошибке записи остаётся прежний статус и появляется сообщение.

### UC-07. Просмотр результата отбора

**Предусловия:** открыта коллекция.  
**Действия:** выбрать фильтр All, Picked, Rejected или Unmarked.  
**Результат:** список содержит только подходящие записи, переключение идёт по этому списку.  
**Альтернатива:** если подходящих кадров нет, показано «Нет фотографий с этой отметкой»; возврат в All показывает всю коллекцию.

### UC-08. Переименование коллекции

**Предусловия:** выбрана коллекция.  
**Действия:** Rename → изменить название → подтвердить.  
**Результат:** название сохранено, фотографии и отметки прежние.  
**Альтернатива/ошибка:** Cancel не меняет данные; пустое или занятое название требует исправления.

### UC-09. Исключение фотографии

**Предусловия:** выбрана фотография.  
**Действия:** Remove from Collection → подтвердить.  
**Результат:** удалена запись этой коллекции, оригинал и запись в другой коллекции остаются. Выбран следующий доступный кадр.  
**Альтернатива/ошибка:** Cancel ничего не меняет; после удаления последней записи отображается пустая коллекция; при ошибке БД запись остаётся.

### UC-10. Удаление коллекции

**Предусловия:** выбрана коллекция.  
**Действия:** Delete Collection → подтвердить.  
**Результат:** удалены коллекция и её записи БД, оригиналы не изменены.  
**Альтернатива/ошибка:** Cancel ничего не меняет; при ошибке БД удаление отменяется; если коллекций больше нет, показан начальный экран.

### UC-11. Повторный запуск

**Предусловия:** созданы коллекции и расставлены отметки.  
**Действия:** закрыть приложение, открыть снова, выбрать коллекцию.  
**Результат:** состав и отметки сохранились. Запоминать последний открытый кадр не требуется.  
**Альтернатива/ошибка:** перемещённые оригиналы остаются записями с недоступным путём; база не очищается автоматически.

### UC-12. Просмотр EXIF

**Предусловия:** выбрана фотография.  
**Действия:** посмотреть панель параметров рядом с изображением.  
**Результат:** доступны производитель и модель камеры, ISO, выдержка, диафрагма, фокусное расстояние, дата съёмки.  
**Альтернатива/ошибка:** отсутствующее поле обозначено «—»; ошибка EXIF не мешает просмотру картинки и отбору.

## 4. Интерфейс

### 4.1. Главное окно

QMainWindow со стандартным стилем Qt. Начальный размер примерно 1100×700, минимальный 850×550 логических пикселей. Расположение строится layout-менеджерами, без фиксированных координат. Язык основных подписей — английский, как в текущей концепции проекта.

| Область | Виджеты | Содержимое |
| --- | --- | --- |
| Слева | QWidget, QVBoxLayout, QListWidget, QPushButton | Коллекции, Create Collection, Rename, Delete Collection |
| Под крупной фотографией | QWidget, QVBoxLayout, QComboBox, QListWidget в IconMode, QPushButton | Фильтр, сетка миниатюр с именами и статусами, Add Photos |
| Центр | QLabel внутри QWidget с layout | Крупная фотография либо текст пустого состояния/ошибки |
| Справа | QWidget, QFormLayout, QLabel | Семь полей EXIF |
| Под фотографией | QHBoxLayout, QPushButton, QLabel | Previous, Next, Pick, Reject, Unmark, Remove from Collection, текущий статус |

QSplitter делит окно по горизонтали на коллекции, центральную рабочую область и EXIF. В центральной области крупное изображение расположено сверху, миниатюры — снизу; между ними можно использовать вертикальный QSplitter. Крупная фотография постоянно находится в главном окне: отдельное окно просмотра и переключение экранов не нужны.

Для миниатюр используется стандартный QListWidget в режиме IconMode: размер иконки около 120×90, ячейки около 150×130 логических пикселей, перенос по ширине и прокрутка. У элемента стандартные QIcon и текст, без отдельных QWidget на каждую карточку. Под миниатюрой показано, например, `[Picked] DSC_0123.JPG`. Цвет может дополнять текст, но не заменять его. Полный путь доступен в tooltip. Выделение одиночное. Щелчок по карточке сразу меняет крупный кадр и EXIF.

Изображение вписывается в QLabel с KeepAspectRatio и SmoothTransformation. При изменении размера окна превью масштабируется заново. Обрезка и растяжение не применяются. EXIF Orientation учитывается при чтении изображения.

### 4.2. Диалоги и меню

- Создание и переименование: QInputDialog.getText. Начальный ввод при переименовании — текущее название.
- Выбор фотографий: QFileDialog.getOpenFileNames с фильтром JPEG/PNG.
- Подтверждение удаления: QMessageBox с Cancel по умолчанию и пояснением, что файлы на диске остаются.
- Ошибки: QMessageBox для БД и операций; проблемы отдельного кадра показываются в области изображения.

File: Create Collection, Add Photos, Exit. Help: About. Действия меню и кнопок вызывают одни и те же обработчики. Дополнительные меню не обязательны.

### 4.3. Правила выбора и фильтра

Коллекции и фотографии упорядочены по id по возрастанию. Новые записи добавляются в конец; ручной сортировки нет. При открытии коллекции устанавливается All и выбирается первый кадр.

При смене фильтра сохраняется выбранный кадр, если он подходит; иначе выбирается первый подходящий. Если отметка вывела текущий кадр из фильтра либо кадр исключён, выбирается первый оставшийся кадр. Если записей нет, картинка и EXIF очищаются. Это простое единое правило, без вычисления сложной истории выбора.

После удаления коллекции выбирается первая оставшаяся. При обычной смене отметки в All текущий кадр не переключается.

## 5. Данные и SQLite

### 5.1. Минимальная схема

Две таблицы: collections и photos. Здесь строка photos означает фотографию **в конкретной коллекции**, а не глобальный объект файла. Поэтому один путь допустим в разных коллекциях и имеет независимые отметки.

| Таблица | Поле | Тип и ограничения | Значение |
| --- | --- | --- | --- |
| collections | id | INTEGER PRIMARY KEY | Идентификатор коллекции |
| collections | name | TEXT NOT NULL UNIQUE, длина 1–80 | Название |
| photos | id | INTEGER PRIMARY KEY | Идентификатор записи |
| photos | collection_id | INTEGER NOT NULL, FK | Коллекция |
| photos | path | TEXT NOT NULL | Абсолютный путь |
| photos | status | TEXT NOT NULL, DEFAULT unmarked, CHECK | Отметка |

Связь: одна коллекция содержит любое количество записей photos, каждая запись принадлежит одной коллекции. Составной UNIQUE запрещает повтор одного пути в одной коллекции.

```sql
PRAGMA foreign_keys = ON;

CREATE TABLE IF NOT EXISTS collections (
    id INTEGER PRIMARY KEY,
    name TEXT NOT NULL UNIQUE
        CHECK (length(name) BETWEEN 1 AND 80)
);

CREATE TABLE IF NOT EXISTS photos (
    id INTEGER PRIMARY KEY,
    collection_id INTEGER NOT NULL,
    path TEXT NOT NULL CHECK (length(path) > 0),
    status TEXT NOT NULL DEFAULT 'unmarked'
        CHECK (status IN ('unmarked', 'picked', 'rejected')),
    UNIQUE (collection_id, path),
    FOREIGN KEY (collection_id) REFERENCES collections(id)
        ON DELETE CASCADE
);
```

Пробелы по краям имени удаляются в программе перед проверкой. Пустая строка, переносы строк и имя длиннее 80 символов не принимаются. Сравнение названий регистрозависимое: Night и night допустимы как разные названия. При конфликте UNIQUE выводится понятное сообщение.

Отдельные таблицы метаданных, пользователей, кэша, настроек и файлов не нужны. Нет миграций, версионирования схемы и общего каталога фотографий. Это новая схема учебного проекта, не совместимая с экспериментальными базами по предыдущей версии ТЗ. Рабочую базу приложение автоматически не удаляет и не перестраивает.

### 5.2. Расположение базы

Используется один файл `flarepick.sqlite3` в пользовательском каталоге данных, определённом через QStandardPaths.AppLocalDataLocation. Перед получением пути задаётся applicationName = FlarePick. Каталог создаётся при запуске, если отсутствует. Пользователь не выбирает и не переключает базы.

База не хранится внутри исполняемого файла или пакета .app. Запуск из другой рабочей директории не должен создавать другую базу.

### 5.3. Работа с БД

Одно соединение sqlite3 в основном потоке. foreign_keys включается при открытии соединения. Запросы параметризованы. Все изменения выполняются с commit; при ошибке — rollback. Пакет добавления выбранных файлов сохраняется одной транзакцией. Дубликаты пропускаются целевым ON CONFLICT(collection_id, path) DO NOTHING; остальные ошибки не скрываются.

Интерфейс показывает новую отметку только после успешного сохранения. При ошибке отображается сообщение, прежние данные остаются. Для блокировок задаётся timeout 1 секунда, чтобы ошибка не выглядела как длительное зависание. Одновременная работа нескольких экземпляров не поддерживается.

Удаление коллекции каскадно удаляет её записи photos. Это удаление строк, а не файлов. Для исключения кадра удаляется одна строка photos. База не содержит изображения или EXIF.

### 5.4. Соответствие README

Фразу о хранении только отмеченных фотографий нужно заменить: база хранит коллекции, пути **ко всем добавленным фотографиям** и их отметки. Иначе после перезапуска пропадали бы кадры Unmarked. Остальной принцип хранения оригиналов не меняется.

## 6. Фотографии и EXIF

### 6.1. Выбор и пути

Поддерживаются .jpg, .jpeg и .png без учёта регистра расширения. Пользователь может выбрать несколько файлов. При добавлении проверяются расширение и существование обычного файла; возможность декодирования проверяется при открытии кадра. Это позволяет не читать целиком каждый файл при импорте.

В БД сохраняется нормализованный абсолютный путь: раскрываются относительные компоненты и символические ссылки, на Windows применяется платформенная нормализация регистра. На macOS/Linux путь принудительно в нижний регистр не переводится. Повтор — совпадение этой строки в текущей коллекции, а не совпадение содержимого.

Копии с разными путями считаются разными фотографиями. Поиска дубликатов по хешу, hard link и всех вариантов файловых псевдонимов нет.

После добавления показан краткий итог: сколько файлов добавлено, сколько уже были в коллекции и сколько пропущено. Отдельного окна на каждый файл не появляется.

### 6.2. Отображение

Файл читается QImageReader с включённым autoTransform. Для крупного просмотра запрашивается уменьшенное изображение под текущую область. В памяти остаются маленькие иконки элементов текущей коллекции и изображение текущего крупного кадра. При переключении крупного кадра предыдущее превью освобождается, его EXIF очищается.

В этой учебной версии чтение миниатюр, крупного кадра и EXIF происходит синхронно в основном потоке. При открытии коллекции программа последовательно создаёт уменьшенные изображения для её записей через QImageReader.setScaledSize, затем назначает их элементам как QIcon. Пропорции сохраняются, ориентация учитывается. Полноразмерные изображения для всех карточек не удерживаются. EXIF читается только для выбранного крупного кадра.

На время построения миниатюр допустима временная недоступность окна и курсор ожидания; после завершения курсор обязательно восстанавливается, в том числе при ошибке. Отдельные потоки, таймеры пакетной загрузки, очередь задач и вызовы processEvents внутри цикла не нужны. Ошибка отдельного файла даёт стандартную иконку-заглушку с именем и не прерывает построение остальных.

При смене коллекции прежние элементы и их иконки освобождаются. Постоянного дискового кэша нет. При смене фильтра достаточно скрыть неподходящие уже созданные элементы без повторного чтения всех миниатюр; при смене статуса обновляются текст и видимость нужного элемента. После добавления файлов допустимо заново построить сетку текущей коллекции. Основной контрольный набор — 30–100 локальных фотографий до 24 Мп; временная пауза при первоначальной загрузке всей коллекции допустима, работа с тысячами файлов на сетевых дисках не является целью.

### 6.3. Недоступные оригиналы

Если оригинал переименован, перемещён, удалён или недоступен для чтения, приложение показывает причину и сохранённый путь. Запись остаётся в БД; можно изменить её статус, исключить её или выбрать другой кадр.

Автоматического поиска нет. Чтобы заменить путь, пользователь исключает старую запись и добавляет файл заново. Старая отметка при этом не переносится. Если файл вернули на прежний путь, он снова открывается при повторном выборе строки или повторном открытии коллекции.

### 6.4. EXIF

Pillow используется только для чтения метаданных. Применяются Image.open в контекстном менеджере, getexif и get_ifd для вложенного Exif IFD. Параметры съёмки не всегда находятся в верхнем словаре EXIF, поэтому вложенный каталог необходимо учитывать.

| Подпись | Поле | Представление |
| --- | --- | --- |
| Make | Make | Производитель камеры |
| Camera | Model | Модель камеры |
| ISO | PhotographicSensitivity / ISOSpeedRatings | ISO 200 |
| Shutter | ExposureTime | 1/250 s, если значение близко к такой дроби; иначе 0.3 s или 1.6 s |
| Aperture | FNumber | f/5.6 |
| Focal Length | FocalLength | 50 mm |
| Date Taken | DateTimeOriginal | YYYY-MM-DD HH:MM:SS |

Для выдержки менее секунды обратная целая дробь применяется, если отклонение не больше 1%; иначе используется десятичное число до четырёх значащих цифр. Для диафрагмы и фокусного расстояния достаточно одного десятичного знака без лишнего .0. Нулевые знаменатели, некорректные числа и неразбираемые даты обозначаются «—».

Метаданные считываются при выборе фотографии, не сохраняются в БД и не кэшируются между запусками. Если поля нет, показывается «—». Если EXIF отсутствует целиком, дополнительно показывается No EXIF data. Дата изменения файла не выдаётся за дату съёмки. Ошибка EXIF не скрывает успешно открывшееся изображение. Запись EXIF не выполняется.

## 7. Состояния и ошибки

| Ситуация | Поведение |
| --- | --- |
| Нет коллекций | Предложение создать коллекцию; добавление и действия с кадром отключены |
| Коллекция пуста | Предложение Add Photos; навигация и отметки отключены |
| Фильтр пуст | Сообщение об отсутствии подходящих кадров; можно выбрать All |
| Файл отсутствует | Заглушка в сетке; текст «File not found» и путь вместо крупной картинки; запись сохраняется |
| Нет прав или ошибка декодирования | Текст «Cannot open image» и путь; переход к другим кадрам работает |
| Неподдержанный формат | Не добавляется; отражён в итогах добавления |
| EXIF отсутствует/не читается | Пустые значения/сообщение; просмотр и отбор продолжаются |
| База недоступна при старте | Сообщение об ошибке и закрытие; база не стирается |
| Ошибка изменения БД | Откат, сообщение, прежние данные в интерфейсе |
| Ошибка чтения коллекции | Сообщение; область кадров очищается, действия с ними отключены; можно снова выбрать коллекцию |
| Пользователь отменил диалог | Никаких изменений, сообщение об ошибке не появляется |

Сообщения должны объяснять, какое действие не удалось. Нельзя молча подавлять все исключения или показывать сохранение там, где commit не завершён. Подробные технические тексты допустимы в консоли, но основные ошибки видны в GUI.

## 8. Структура программы

```text
flarepick/
    main.py
    gui.py
    database.py
    metadata.py
    requirements.txt
    README.md
    TECHNICAL_SPECIFICATION.md
    LICENSE
```

| Модуль | Ответственность |
| --- | --- |
| main.py | Создание QApplication, путь базы, запуск окна, завершение |
| gui.py | Главное окно, диалоги, обработчики, синхронное создание миниатюр, чтение текущего изображения через Qt, масштабирование |
| database.py | Соединение, создание таблиц, CRUD коллекций и записей, фильтрация |
| metadata.py | Чтение и форматирование EXIF через Pillow |

Этого разделения достаточно. ORM, контроллеры, отдельные service/repository-слои, asyncio, модели на каждый вид данных и система событий не нужны. БД может возвращать sqlite3.Row или обычные словари.

Основные операции database.py: получить коллекции; создать/переименовать/удалить коллекцию; получить фотографии коллекции с необязательным фильтром; добавить пути; изменить статус; исключить запись. SQL хранится в database.py, а не внутри обработчиков кнопок. Изменение/удаление фотографии проверяет её id и collection_id.

В окне достаточно хранить текущий id коллекции, id фотографии, выбранный фильтр и текущий QImage. Полноценная система моделей состояния не нужна. При программном обновлении списков следует временно блокировать их сигналы, чтобы не запускать обработчики с промежуточным выделением.

## 12. Критерии готовности

Приложение считается готовым к сдаче, если:

1. Запускается из исходников по README и из проверенной сборки на основной ОС.
2. Можно создать, переименовать, открыть и удалить коллекцию.
3. Можно добавить несколько JPEG/PNG, увидеть сетку синхронно загруженных миниатюр и выбирать кадры для крупного просмотра.
4. Работают Pick, Reject, Unmark и фильтр; отметки сохраняются после перезапуска.
5. EXIF отображается при наличии, отсутствие не вызывает ошибку приложения.
6. Исключение записи и удаление коллекции не меняют оригиналы.
7. Дубликаты пути, отмена диалога, пропавший файл и ошибки БД обрабатываются.
8. README описывает реализованные функции, зависимости, запуск, сборку, форматы и ограничения.

На защите достаточно показать: создание коллекции → добавление кадров → сетка миниатюр → выбор кадра и просмотр с EXIF → три отметки и фильтр → перезапуск с сохранением → исключение записи без удаления файла. Затем показать две таблицы и разделение кода по модулям.

Это спецификация небольшого учебного приложения. Она не требует продуктовой инфраструктуры, профессиональной производительности или выпуска на всех платформах за две недели.
